# Тяга — силовой журнал тренировок

Журнал тренировок и аналитика силового прогресса: подходы, вес, повторы, RIR, история и программы. React 19, TypeScript, Vite, Cloudflare Workers и D1 (SQLite). Без внешнего AI API, рекламы и аналитических трекеров.

## Ключевые возможности

### 1. Установка на домашний экран iPhone
- Web App Manifest, метатеги Safari, standalone-режим и safe-area insets.
- Пошаговый гид: «Поделиться» → «На экран „Домой“».
- Установка не означает полный офлайн-режим: для запуска веб-приложения и сохранения тренировок в облако нужна сеть. Черновик хранится в браузере; автономная SQLite предусмотрена в Android-приложении.

### 2. Контроль массы тела и тренд
- Ежедневные взвешивания и сглаживание EMA 7 дней, уменьшающее влияние суточных колебаний.
- Недельный темп изменения массы, SVG-график и линия целевого веса.
- Замеры с заметками и быстрым вводом со степперами `±0.1` / `±0.5` кг.
- Вкладка «Вес тела» внутри «Прогресса»: компактный график по календарным датам, редактирование замеров, подтверждение удаления и ввод с десятичной запятой. Цель не сжимает масштаб графика; ошибки хранилища видны рядом с формой. [Описание и проверка](<docs/progress-bodyweight.md>).
- Замеры и цель сохраняются в аккаунте, с очередью изменений без сети, экспортом JSON и выбором версии при конфликте устройств. Старые локальные записи переносятся без удаления оригинала. На Android для переноса между устройствами нужно подключённое облако. [Подробности](<docs/daily-workflow.md>). Новый журнал пустой: выдуманные взвешивания не подставляются.

Программа v2 из пяти тренировок содержит **126 рабочих подходов в неделю** (22 + 29 + 24 + 26 + 25). Шесть кистевых подходов исходного плана в шаблон не включены.

Единый журнал веса теперь используется профилем и новыми упражнениями; прошлые тренировки сохраняют свой снимок массы. Полная копия v4 включает вес, цель, программы, настройки и тему; восстановление показывает различия до записи. Для Android добавлены системные уведомления отдыха с `+30 с` и возвратом к подходу. Напарники могут принять челлендж на четыре недели с собственными неизменными целями. [Поведение, ограничения, проверка старых PR и выпуск](<docs/reliability-and-challenges.md>).

### 3. Разминочная лесенка
- Пустой гриф (20 кг) × 10.
- Около 45% × 5, 68% × 3, 83% × 2 рабочего веса.
- Для рабочих весов от 90 кг: около 92% × 1.
- Рабочий подход и раскладка стандартных блинов на сторону: 25, 20, 15, 10, 5, 2.5, 1.25 кг.
- Это настраиваемый тренировочный ориентир, а не индивидуальное медицинское назначение.

### 4. Разгрузочная неделя
- Анализ частоты сессий, рабочих подходов и отказных подходов (RIR 0) за 30 дней.
- Три шаблона: сокращение объёма, сокращение интенсивности и активное восстановление.
- Калькулятор изменения тоннажа и применение выбранного варианта к черновику.

### 5. Анатомия и участие мышц
- Карта тела спереди и сзади: грудь, дельты, спина, корпус, руки и ноги.
- Основные движители, ассистенты и стабилизаторы учитываются отдельно.
- Редакционная разметка с источниками, не клинический атлас: приложение не измеряет точные проценты активации, гипертрофию или восстановление.

### 6. Профиль атлета
- Имя, масса тела, часовой пояс и выбор акцентной темы.
- Сохранение профиля и выход из аккаунта.
- Отдельная вкладка «Друзья»: приглашения по коду или ссылке, взаимное принятие заявок, статус «В зале» на 2 часа, лента сводок тренировок за 30 дней и респекты.
- Недельный ориентир команды настраивается каждым атлетом отдельно. Можно пригласить напарников на одно время, тренироваться в разных залах и собрать общий итог из сохранённых тренировок.
- Почта, вес тела, заметки и детали подходов не передаются напарникам. Нет выдуманных друзей и случайных статусов. Удаление напарника закрывает взаимный доступ.
- «Программы» и «Друзья» доступны в нижней навигации телефона и боковой панели компьютера. Карточки, реакции и шкала команды анимированы через Motion с учётом reduced motion.
- [Устройство раздела друзей и выпуск](<docs/friends.md>): для облачного обновления нужна миграция `0007_wise_rhodey.sql`; Android использует подключённое облако, без него предлагает подключение в профиле.

### 7. Прогресс и ежедневная работа
- Обзор регулярности, силы и нагрузки за 4/8/12 недель; сопоставление с равным предыдущим периодом.
- Нагрузка по мышцам и анатомия объединены в одном разделе. Сплошная линия веса проходит через взвешивания, EMA показана отдельно пунктиром.
- Отмена удаления упражнения/подхода сохраняется в черновике; Enter переводит фокус к следующему числовому полю.
- Калькуляторы и редкие настройки собраны в хабе «Инструменты».

### 8. Аналитика силы
- График e1RM для подходящих упражнений и личные рекорды.
- Баланс Жим / Тяга и Верх / Низ.
- 16-недельная карта тренировочной активности.

## Технический стек

- **Фронтенд:** React 19, TypeScript, Motion, Lucide, CSS с дизайн-токенами.
- **Night Session:** графитовый фон, лайм, оригинальная SVG-графика дисков, адаптивные экраны и поддержка уменьшения движения.
- **Шрифты:** локальные, с родной кириллицей: Fira Sans Extra Condensed для заголовков и крупных цифр, Onest для интерфейса, JetBrains Mono для кодов. Семейства заданы токенами в [fonts.css](<src/styles/fonts.css>). Внешний CDN не нужен.
- **Звук:** Web Audio API, тактильная отдача — `navigator.vibrate`.
- **Web:** Cloudflare Worker + D1, серверные ревизии, сессионные cookie.
- **Android:** автономный движок `sql.js` (SQLite в WASM), облачная синхронизация по желанию пользователя.
- **Черновики:** версионированное автосохранение в браузере, отдельно для аккаунта.

Правила учёта подходов, нагрузки, экспорта и происхождения каталога описаны в [методике](<docs/methodology.md>).

### Безопасное обновление

1. Авторизовать Wrangler и проверить аккаунт, Worker и **production D1 UUID выше**. Не заменять binding другой базой и не использовать legacy-конфигурацию.
2. Перед Vite-сборкой сохранить текущие Android APK и парный JSON версии **вне `dist`**. Сборка очищает assets. Если нового подписанного APK нет, вернуть сохранённую пару в свежий `dist/client`; версия веб-пакета не является версией APK.
3. Проверить существующую схему и журнал миграций через `SELECT`. Перед необходимыми миграциями на непустой базе сохранить приватный экспорт / Time Travel bookmark. Если схема актуальна, миграции не нужны. Не импортировать локальную SQLite поверх production. Первое развёртывание использует только новую, проверенную пустую D1.
4. Выполнить проверки и собрать проект; восстановить APK и метаданные, затем проверить JSON, ZIP-целостность и хеши. Сохранённый APK **1.2 / versionCode 3** — прежний Android-релиз, не новая сборка Night Session; его интерфейс и настройки облака не изменяются этим web-deploy.
5. Выполнить dry-run и отдельно задеплоить по новой production-конфигурации. Проверить публичную страницу, её JS/CSS/шрифты, анонимный auth API и скачивание APK.

```bash
# Вход по коду без localhost callback; обычный wrangler login тоже подходит
npx wrangler login --device
npx wrangler whoami --config wrangler.production.jsonc
npx wrangler d1 info DB --config wrangler.production.jsonc

# После проверки базы и сохранения APK:
npx tsc --noEmit
npm test
npm run build

# При необходимых миграциях — только после проверки схемы и backup:
# npm run db:migrate:cloud

# Здесь восстановить сохранённые APK и метаданные в dist/client.
# Только после их проверки:
npm run deploy:cloud:check
npm run deploy:cloud
```

`deploy:cloud` теперь выполняет **только деплой**: не запускает сборку, копирование APK или миграции. [copy-apk.mjs](<scripts/copy-apk.mjs>) — отдельный ручной инструмент для явно собранного Android APK; при его отсутствии скрипт лишь предупреждает. Не используйте его вместо восстановления сохранённой пары. `wrangler d1 migrations list --remote` в текущем Wrangler инициализирует журнал миграций; это не строго read-only проверка.

[Локальная конфигурация](<wrangler.jsonc>) и автоматически собранная server-конфигурация не подходят для production: у них локальная идентичность и другой backend.

## Быстрый запуск для разработки

Нужен Node.js 22.13+ (рекомендуется Node.js 24).

```bash
npm ci
npm run build
npx wrangler d1 migrations apply DB --local --config wrangler.jsonc
```

В двух терминалах:

```bash
# Терминал 1: локальная база и API
npm run preview:server

# Терминал 2: Vite
npm run dev
```

Открыть `http://localhost:5173`. Это отдельная локальная база; production D1 не затрагивается.

## Тесты и валидация

```bash
npx tsc --noEmit
npm test
npm run build

# Изолированные UI-регрессии: все API-запросы перехвачены fixtures
npx playwright test tests/e2e/design.spec.ts --reporter=line
```

Остальные E2E делают настоящие запросы и могут создавать/изменять записи. Запускайте полный `npm run test:e2e` только с отдельной тестовой D1 и тестовыми аккаунтами: Playwright вне CI может использовать уже запущенные серверы. Не направляйте такие тесты в production или личную базу.

## Android APK

```bash
npm run build:android
cd android && ./gradlew assembleDebug
```

Выходной путь: `android/app/build/outputs/apk/debug/app-debug.apk`. Для обновления уже установленного приложения нужны прежняя подпись и увеличенный Android `versionCode`; другая подпись может потребовать удаления приложения и потери телефонной SQLite. Сохранение прежнего APK на сайте не обновляет его встроенный интерфейс.
