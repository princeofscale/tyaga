# Тяга

Лёгкий журнал тренировок на русском: подходы, вес, повторы, RIR, история и покрытие недельных ориентиров. React 19 + TypeScript + Vite; Cloudflare Worker + D1. Без внешнего AI API, рекламы и аналитических трекеров.

## Что работает

- **Аккаунт:** регистрация, вход, профиль, cookie-сессии на 30 дней, смена пароля и одноразовый код восстановления. Прежняя история сохраняется.
- **Первая тренировка:** сразу после сохранения видны выполненные подходы, общий тоннаж, рабочая/разминочная работа и участие мышц.
- Запись тренировок: рабочие и разминочные подходы, вес, повторы, RIR, заметки и дата.
- Таймер отдыха переживает reload; черновик показывает реальный статус сохранения. Длительность можно исправить вручную.
- Серверное сохранение, редактирование, повторение фактических подходов и удаление; revision защищает от одновременных изменений.
- Новый интерактивный атлас спереди/сзади, 10 зон и 32 анатомические записи: прямые подходы, помощь и стабилизация отдельно, фильтр RIR и выбор недели.
- **«Баланс недели»**: объяснимый план на 20 / 40 / 60 минут; прогноз покрытия ориентиров после выполнения предложенных подходов.
- Вес одной гантели / штанги, явные стороны, помощь в подтягиваниях, идентификатор машины и контекст массы тела.
- Прогресс внутри одной версии и правила записи, e1RM только для разрешённых упражнений, экспорт собственных данных в JSON.
- 31 уточнённый вариант упражнения с русскими/латинскими названиями мышц, ролями, источниками и ограничениями. Версия старого каталога сохраняется в истории.
- Локальные кириллические Manrope / Unbounded, лёгкие анимации Motion, адаптивная версия и уменьшение движения.
- Локальная база wger: 918 упражнений, поиск, фильтры, пагинация, атрибуция, запись повторных подходов для поддерживаемых вариантов.
- **Все 949 текущих упражнений на русском**, с русскими алиасами и английскими оригиналами для поиска. Названия редакционно переведены с помощью ИИ, описания wger — машинно; исходный текст и лицензия доступны в карточке.
- **Программы:** недельное расписание, четыре редактируемых стартовых шаблона, свои подходы и отдых; запуск из программы и предложение двойной прогрессии для подходящих свободных весов.
- **26 записей wger проверены по источникам:** явные роли и правила веса, новые версии без пересчёта старой истории. Остальные записи помечены непроверенными.
- **Apple Watch:** локальный импорт Apple Health XML/ZIP, выбор своей силовой сессии, пульс и калории в деталях тренировки. Это импорт, не живая синхронизация.
- Личные упражнения с алиасами, правилами веса и сторонами, избранное с сохранением в аккаунте; версии определений не переписывают прошлую историю. Можно выбрать базовое движение для своего тренажёра; такой выбор явно отмечен как пользовательский.
- Время подхода в секундах и необязательная дистанция для кардио и удержаний. Неизвестный RIR остаётся пустым.
- **Импорт Strong / Hevy / FitNotes CSV**, предпросмотр и сопоставление, явные единицы, защита от повторного импорта. JSON версии 3 переносит тренировки, программы, свой каталог, избранное и по выбору настройки.
- Опциональные браузерные WebMCP-инструменты для чтения своего баланса и подготовки черновика.

Новый профиль открывает пустой личный журнал. «Посмотреть пример» явно включает демонстрационные данные, которые не записываются в базу и не попадают в экспорт. Завершённые тренировки, профиль, программы и цели сохраняются в D1; незавершённый черновик хранится в браузере отдельно для аккаунта. Разминка входит в общий тоннаж и отдельный счётчик подготовки; покрытие недельных ориентиров и e1RM используют рабочие подходы.

## Быстрый запуск

Нужен Node.js 22.13+ (проверено на Node.js 24).

```bash
npm ci
npm run build
npx wrangler d1 migrations apply DB --local --config wrangler.jsonc
```

В первом терминале:

```bash
npm run preview:server
```

Во втором:

```bash
npm run dev
```

Открыть `http://localhost:5173`. Сервер разработки использует отдельную локальную базу и тестовую идентичность. **Не разворачивайте `server/local.ts` в интернете.** Production-сборка использует `server/index.ts`, который требует идентичность от доверенной платформы Sites и проверяет владельца каждой записи. Приватный Site сначала требует аккаунт платформы, затем вход в Тягу. При самостоятельном хостинге нужен доверенный ingress; прямому публичному запросу нельзя позволять подставлять `oai-authenticated-user-id`.

## Android (APK)

Приложение для телефона работает **без сервера и без интернета**: тот же API (`server/index.ts`) выполняется внутри приложения на SQLite (sql.js, `src/device/`), база хранится на телефоне. Профиль создаётся автоматически при первом запуске. Резервная копия — «История → Экспорт JSON», файл уходит в окно «Поделиться» (Telegram, Диск и т.п.); восстановление — «Импорт истории».

Нужны Node.js 22+, JDK 21 и Android SDK 36 (путь — в `android/local.properties`, `sdk.dir=...`).

```bash
npm ci
npm run build:android
cd android && ./gradlew assembleDebug
```

APK: `android/app/build/outputs/apk/debug/app-debug.apk`. Отладочный APK подписан ключом машины, на которой собран: чтобы обновление ставилось поверх без потери данных, собирайте на одной машине (или заведите общий release-ключ).

## Проверка

```bash
npm run typecheck
npm run build
npm test
```

50 unit/API проверок используют production Worker и настоящую локальную D1: миграции, конфликты, idempotent retry, удаление, owner isolation, timezone/DST, нагрузка/стороны, версии истории, ошибки Storage, программы, импорт, аккаунт, отзыв сессий, разминку и XML Apple Health. CI также запускает 14 браузерных сценариев.

```bash
npx playwright install chromium
npm run test:e2e
```

Playwright сам запускает production preview интерфейса и локальный Worker с отдельной `.wrangler/e2e` базой. Остановите обычные dev-серверы перед запуском, чтобы тесты использовали свою базу. При системном Chromium можно передать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`. Workflow: [Checks](.github/workflows/checks.yml).

Сборка: `dist/client` — интерфейс; `dist/server/index.js` — Worker. Миграции Drizzle находятся в `drizzle/`. Конфигурация Sites — `.openai/hosting.json`. Продуктовые данные и секреты не находятся в репозитории.

## Отличие от конкурентов

Исследованы [OpenGym](https://github.com/DuarteSantos8/openGym), его [форк с AI Coach](https://github.com/alexpcosta/opengym), [LiftLog](https://github.com/LiamMorrow/LiftLog) и [Workout.lol](https://github.com/workout-lol/workout-lol). Карта мышц сама по себе уже есть у OpenGym. Наша ставка — маленький, быстрый и проверяемый сценарий: **история → пробелы в недельной нагрузке → короткая тренировка → видимый прогноз**. Это направление продукта, а не заявление об отсутствии похожих функций во всех приложениях.

Подробнее: [исследование конкурентов](docs/competitors.md), [методика и версии истории](docs/methodology.md), [источники базы упражнений](docs/exercise-data-sources.md), [ответ на ревью](docs/review-response.md), [проверка](docs/verification.md), [аккаунт, разминка и Apple Watch](docs/product-v1.4.md).

Каталог — редакционная анатомическая разметка с источниками, без независимой сертификации специалистом. Участие мышцы, ЭМГ и гипертрофия не равны. Приложение не вычисляет «100% точные проценты активации», рост или восстановление. Старые неоднозначные веса не угадываются и не складываются с новым внешним объёмом.

Код реализован самостоятельно. Векторные данные атласа использованы под MIT; каталог wger — под лицензиями отдельных записей. См. [дизайн и архитектуру](docs/design-and-catalog.md) и [third-party notices](THIRD_PARTY_NOTICES.md). Компоненты используют React и Lucide с их исходными лицензиями.
