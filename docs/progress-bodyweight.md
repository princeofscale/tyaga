# Прогресс и масса тела

Этот PR подготовлен поверх ветки PR #5; исправления замечаний к друзьям остаются отдельным коммитом в #5. Деплой и миграции production не выполняются.

## Исправления

- Графики веса и силы используют общую календарную шкалу: расстояния между датами пропорциональны прошедшим дням. Высота — 230 px, включая на широком экране. Одна точка располагается в центре.
- Цель массы тела не участвует в масштабе замеров. Если она вне диапазона, отображается подпись; линия цели рисуется только внутри видимой шкалы. Выбранное взвешивание и заметка находятся в потоке страницы, не перекрывают график. Выбор доступен мышью, касанием и через клавиатуру в списке точек.
- В «Прогрессе» есть отдельная вкладка «Вес тела»; быстрый инструмент использует тот же журнал. Пустой журнал не подставляет выдуманный вес. Ввод принимает десятичную запятую и точку, диапазон 20–500 кг включительно, дату в часовом поясе аккаунта. Повторное сохранение даты обновляет её запись и позволяет очистить заметку. Удаление требует подтверждения.
- Имена ключей, формат записей, ID и заметки прежних взвешиваний сохраняются. Ошибки записи показываются пользователю, форма и прежняя история сохраняются. Повреждённые или недоступные данные не заменяются пустой историей.
- EMA учитывает календарные интервалы между фактическими замерами; пропущенные дни не создаются. Это визуальное сглаживание, не измерение состава тела. Темп оценивается регрессией замеров за последние 28 дней: минимум 3 даты, охватывающие 7 дней. При недостатке данных отображается «—», а не выдуманный темп по двум точкам.
- Вес и цель синхронизируются с аккаунтом через очередь и ревизии; масса тела в профиле не изменяется автоматически. [Текущий процесс синхронизации](<daily-workflow.md>).
- Сплошная линия проходит через взвешивания; EMA изображается отдельным пунктиром. Выбор подписан «Выбрать запись».
- Сила: учитываются выполненные рабочие подходы, повторы относятся к лучшему подходу, для упражнений на время отображаются секунды, для упражнений без отягощения — повторы, для тренажёра с помощью лучший результат — меньшая помощь. Незавершённые сессии не создают нулевую точку.
- Тоннаж в статистике, календаре и рекордах использует общие правила журнала: рабочие подходы, число гантелей и выполненных сторон, исключение неподходящих режимов записи. Нулевой предыдущий период не выдаётся за рост на 100%. Категории рекордов опираются на мышцы каталога, а не подстроки названия.
- Motion анимирует вход в разделы и линию графика, учитывает уменьшение движения и не запускает бесконечных анимаций.

## Проверки

Обязательные: `npx tsc --noEmit`, `npm test` (теперь автоматически пересобирает Worker), `npm run build`. Регрессии доменных правил: `tests/bodyweight.test.ts`, `tests/progress-series.test.ts`, `tests/personal-records.test.ts`.

`tests/e2e/progress.spec.ts` перехватывает все API-запросы: это тестовые замеры и аккаунты, production не используется. Проверяется сохранение через перезагрузку, редактирование/очистка заметки, подтверждение удаления, ошибка хранилища без потери ввода, два замера и далёкая цель, выбор точки, единые расчёты статистики и размеры 320/390/768/1440 px. Скриншоты — `artifacts/progress/`.

Профиль и новые упражнения используют общий журнал веса; сохранённые тренировки сохраняют свою массу. Полная копия v4, перенос и обновлённые проверки описаны в [reliability-and-challenges.md](reliability-and-challenges.md).
