## R05-REQ01 — названия Strong/Hevy узнаются

**Сделано.** `src/domain/ImportNameMatcher.ts`: таблица правил «название без оборудования + оборудование из скобок → упражнение каталога» (Barbell/Dumbbell/Cable/Machine/Smith/Kettlebell/EZ…), плюс точные ответы базы (`/api/exercises/resolve`), плюс ближайшие по словам. Вердикт на каждое имя: `matched` (применяется), `variant` (близкий вариант того же движения — применяется, но показан отдельным блоком «Близкие варианты»), `ask` (есть похожие, но уверенности нет — спрашиваем), `own` (в каталоге ничего похожего — отдельная запись). Оборудование решает, а не «похоже»: `Overhead Press (Dumbbell)` → жим гантелей, `(Barbell)` → штанга; голое `Deadlift` без оборудования только предлагается.
Предпросмотр (`HistoryImporter`): «Сопоставлено N из M · нужно решить K», блок «Нужно решить» со списком ближайших вариантов и выбором, второй вопрос про вес гантелей («вес одной гантели?») рядом с вопросом про штангу, метка тренажёра/блока подставляется сама («Из файла (Machine)») — вместо ошибки «Укажи тренажёр». Даты сессий в предпросмотре — «15 нояб. 2025».
Вес у упражнений «только вес тела»: сервер не принимает внешний вес. «Pull Up» с весом в файле целиком уходит в «Подтягивания с дополнительным весом» (одна запись на всю историю); у остальных вес не теряется молча — в предпросмотре есть предупреждение, максимум записан в заметку к упражнению.
**Тесты.** `tests/round-05.test.ts`: годовой файл (генератор `tests/fixtures/gen-year-csv.mjs`, 240 тренировок, 52 имени) — сопоставлено ≥40, нерешённых ≤12; семь имён из ТЗ → каталог; гантели ≠ штанга; спорные не склеиваются. Тест на настоящем воркере (Miniflare, чанки по 30): импорт 240 за несколько секунд, «Мои» ≤12, `Pull Up`, `Lat Pulldown (Cable)`, `Hanging Leg Raise`, `Leg Press (Machine)`, `Face Pull (Cable)`, `Calf Raise (Machine)`, `Back Extension` не «Мои», подтягивания — одна запись, метка тренажёра есть, вес сохранён в заметке. e2e: счётчик, «Нужно решить», даты без ISO, «Мои» ≤12 после импорта.
**Ограничения.** На годовом файле QA без ответов базы остаётся 9 спорных + 5 своих (14 > 12): ≤12 достигается либо точными совпадениями базы wger (в тестах подставлены для Plank, Dip, Kettlebell Swing, Farmers Walk, Good Morning), либо выбором пользователя в блоке «Нужно решить». Реальные 918 записей wger локально не проверялись. Таблица синонимов покрывает распространённые названия Strong/Hevy, не все существующие. Спорные по умолчанию остаются отдельными записями — осознанно, чтобы не склеивать разные движения (например, Front Squat с приседом).

## R05-REQ02 — «не учтено» и массовая разметка «Моих»

**Сделано.** `MuscleCoverage` считает подходы упражнений без мышц; «Прогресс → Мышцы» и «Закрыть пробелы» показывают «Не учтено: 3 упражнения, 9 подходов» и кнопку «Разметить», ведущую в «Упражнения → Мои» сразу в режиме разметки. В «Мои»: «Без разметки мышц: N из M», «Разметить несколько», чекбоксы, «Выбрать без разметки», «Назначить группу» и «Это то же, что…» (упражнение каталога). Сохранение идёт через тот же `PUT /api/custom-exercises` (`PersonalExerciseMarking`): название, правило веса и происхождение импорта сохраняются. Упражнения «на время» получают только группу. Группы мышц «Моего» без разметки каталога считаются основными в «Рабочих подходах по зонам»; старая история (снимок без мышц) подхватывает актуальную версию семьи (`ExerciseCatalog.adoptFamilies`), размеченные снимки не трогаются.
**Тесты.** unit: «Пресс» 0 → >0 после группы и после каталожного движения, «не учтено» исчезает, происхождение не теряется, версия семьи. e2e (390×844): неделя 19–25 окт., «Не учтено: 3 упражнения, 9 подходов», разметка двух упражнений группой и третьего через каталог за два действия, «Пресс» 0/6 → 6/6.
**Ограничения.** «Это то же, что…» даёт мышцы каталога, но не сливает историю в один ряд «Силы» (у «Моего» своё правило веса); 1ПМ у «Моих» по-прежнему отключён. Разметка — последовательные запросы, на 46 упражнений это 46 коротких PUT с индикатором «Сохраняем N из M».

## R05-REQ06 — восстановление из копии

**Сделано.** Своё окно «Восстановление из копии» (только JSON, без слов про Strong/Hevy); `RestorePlan` считает «Новых N · Уже есть M · Отличаются K» отдельно по тренировкам, весу, программам, своим упражнениям и избранному; при отсутствии нового — «Ничего нового: все 240 тренировок уже в аккаунте»; даты в общем формате; итог («Ничего не добавлено…» или «Восстановление завершено» с построчным итогом) остаётся, пока его не закроют.
**Тесты.** unit: классификация, фраза «ничего нового», новые программы не считаются «ничем»; e2e: импорт года → «Скачать полную копию» (240) → восстановление тем же файлом: заголовок, «Новых 0 · Уже есть 240», фраза, итог не пропадает через 1,5 с, число тренировок не меняется.
**Ограничения.** Тренировка с тем же id, но другим содержимым считается «отличается» и остаётся как в аккаунте — сервер не перезаписывает существующие (как и раньше).

## R05-REQ07 — баннер «Отменить импорт»

**Сделано.** Баннер говорит, к какой операции относится: «Отмена удалит 240 тренировок, добавленных 10 нояб. в 16:00»; если после него был импорт или восстановление, которое ничего не добавило, строка «Восстановление … ничего не добавил — отмена относится к импорту от …»; новый добавивший импорт заменяет баннер; перед удалением — подтверждение с числом («Удалить 240 тренировок, добавленных …?», кнопки «Убрать 240» и «Не надо»).
**Тесты.** unit: формат момента; e2e: пояснение, подпись после пустого восстановления, подтверждение, «Не надо» ничего не удаляет, «Убрать 240» → тост и пустой журнал.
**Ограничения.** Пометка «последнее восстановление ничего не добавило» живёт до перезагрузки страницы; после перезагрузки баннер всё равно подписан датой и числом своей партии.
