## Устройство продукта

React 19 + strict TypeScript + Vite; UI в [src](<../../src>), вычисления/парсинг в domain-классах. [App](<../../src/App.tsx>) связывает журнал, программы, прогресс, инструменты, аккаунт и социальные функции. [WorkoutView](<../../src/components/WorkoutView.tsx>) отвечает за ввод и активный черновик. Локальные шрифты Onest/Fira Sans Extra Condensed/JetBrains Mono, спортивная тёмная тема, Motion с reduced-motion.

Веб-клиент обращается к same-origin API через [ApiClient](<../../src/services/ApiClient.ts>): таймаут, проверка ответа, ошибки и событие истечения сессии. Worker [API](<../../server/index.ts>) проверяет идентичность, Origin/JSON, активную сессию, владельца данных и ревизии. D1 хранит payload тренировок/программ и отдельные документы. [Черновик](<../../src/lib/draft.ts>) сохраняет тренировку, часы, отдых и undo локально; ключ привязывается к аккаунту на уровне приложения.

Android устанавливает [локальный backend](<../../src/main.tsx>) [localBackend.ts](<../../src/device/localBackend.ts>) со SQL.js до рендера. [Cloud sync](<../../src/device/cloudSync.ts>) отдельно реплицирует документы с курсорами и `machines-v1`; [серверный sync](<../../server/SyncService.ts>) проверяет документы и владельца. Журнал веса использует отдельную атомарную очередь/CAS/tombstones, не подменяется старым last-write-wins протоколом тренировок.

Поддерживаются запись веса/повторов/RIR/времени, исторические snapshots/каталоги, программы/прогрессия, разминочная лесенка, отмена удаления, история, полная JSON-копия и предварительный импорт, масса тела, ориентиры нагрузки, e1RM сопоставимых вариантов, конкретные станции тренажёров, стороны/ROM, социальные встречи/челленджи/комнаты, локальный видеоанализ. Наличие функции в коде не означает её независимую UI-проверку в этой работе.

## Методика и ограничения

Обязательны [AGENTS](<../../AGENTS.md>), [README](<../../README.md>), [методика](<../methodology.md>), [биомеханика/объём](<../biomechanics-and-volume.md>), [аналитика/техника](<../analytics-and-technique.md>), [ежедневная работа](<../daily-workflow.md>), [надёжность](<../reliability-and-challenges.md>). Математика не переносится в JSX. Старые каталоги/снимки/экспорты не переписываются, недоказанные коэффициенты стимула/восстановления не вводятся. Машины, стороны и явно различающийся контекст не сливаются в общий рекорд. Разминка отличается от рабочих подходов. RIR неизвестен, если не введён; отсутствие данных не равно нулю.

Веб-версия не является полностью offline-first: черновик локален, облачное сохранение требует сети. Android SQLite автономна, но социальные функции требуют облака. По задумке и исходному коду видео и кадры не должны отправляться на сервер, однако экспериментальные свидетельства пока ограничены тестом пустого видео (проверено только отсутствие POST-запросов вне API при замокированном API, что не доказывает отсутствие загрузок во всех сценариях или общую приватность); официальная модель может загружаться при первом анализе. Утверждать проверку Android/физического телефона без выполнения нельзя.

## Правило одного раунда

**Один раунд = одно полное основное сообщение агента-пользователя агенту-разработчику.** Число требований внутри не ограничено. QA-fixes/замечания при приёмке — продолжение того же раунда. Нельзя считать отдельный тест/коммит/подзадачу новым раундом или заранее выдумывать 30 жалоб.

Порядок: свежий реальный UI → сохранённый целиком оригинал ТЗ → стабильные `RNN-REQxx` → весь объём engineering → mandatory checks/релевантный E2E → независимый QA на каждый ID → независимая user acceptance → lead diff review/локальный commit → следующий раунд. FAIL/PARTIAL не превращаются в PASS компиляцией.

Промежуточные отчёты после 5/10/15/20/25/30 принятых раундов. Если полезные изменения действительно исчерпались — честная остановка с доказательствами, не filler.
