**QA-R03-01 — офлайн-запуск не работает сразу после первого входа (высокая).**
Сценарий из ТЗ: «войти с сетью → закрыть вкладку → отключить сеть → открыть адрес» (`s7b-firstlogin.mjs`, шаги F1–F4). Профиль для офлайн-входа пишется (`tyaga-offline:session`) только при **следующей онлайн-загрузке страницы**, а не при регистрации или входе.
- F1: сразу после регистрации в `localStorage` есть `tyaga-offline:data:<id>` (330 байт), но нет `tyaga-offline:session`.
- F2: новая вкладка при недоступном API показывает экран «Тяга | Запрос не завершился… | Повторить» вместо приложения. SW при этом контролирует страницу, оболочка в кэше.
- F3/F4: после одной дополнительной онлайн-загрузки ключ появляется, и офлайн-запуск работает (баннер «Нет связи…»).
- Тот же эффект независимо воспроизведён в `s7-security` (S4/S5).
- Последствие: новый пользователь, зарегистрировавшийся и сразу закрывший приложение, при первом офлайн-запуске получает ошибку — именно тот сценарий, который описывает ТЗ.
- Предложение: записывать `tyaga-offline:session` в момент успешной регистрации/входа.

**QA-R03-02 — запуск из программы подставляет придуманные значения (средняя).**
`s10-program-start.mjs`, `s10-program-start-360.png`. Программа «Жим штанги лёжа» + «Тяга верхнего блока», запуск кнопкой «Начать»:
- «Тяга верхнего блока» (истории нет): поле повторов = «10», поле RIR = «2» как введённые значения;
- «Жим штанги лёжа»: подходы 77,5 × 8 / 8 / 8, а «Прошлый» показывает 8 / 8 / 7.

ТЗ R03-REQ02 (а) и (б) прямо говорят, что без истории повторы и RIR не подставляются, а подход N берёт подход N из «Прошлого». В свободной тренировке это выполнено, в запуске из программы нет.
Оговорка: возможно, это сознательно, как «план программы» (в карточке написано «Повторять структуру, брать веса из истории»). Тогда ТЗ нужно уточнить. Что именно запишется в историю, я не доказал: финиш этого сценария блокировал отдельный запрос «Укажи тренажёр для «Тяга верхнего блока»» (штатное правило сравнения машин, `s10b-program-rir.mjs`), значит, «✓ записывает RIR 2» — вывод по значению поля, а не по записи на сервере.

`s7-security.mjs`, `s7b-firstlogin.mjs` (F6).
- В `localStorage` лежит в открытом виде: `tyaga-offline:session` (профиль: имя и почта, ~200 байт) и `tyaga-offline:data:<id>` (тренировки, настройки; у меня 34 КБ после импорта 21 тренировки). Явного шифрования нет: любой скрипт на origin (например, при XSS) может это прочитать.
