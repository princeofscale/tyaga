## Подробности по требованиям

**REQ01.** `src/domain/WorkoutDiscard.ts`: `needsConfirmation = !!draft.editing || hasRecordedSets`. Два прежних пути отмены сведены в один (`requestDiscard` в `WorkoutView`, `discardDraft` в `App`), старый `modal==="discard"` удалён. Диалог один: «Отменить тренировку?» / «Отменить изменения?», кнопки «Да, отменить …» и «Продолжить». После отмены — «Сегодня» с навигацией (`in-workout` ставится только при `view==="workout" && draft`).
Решение: введённые, но не отмеченные значения вопроса не вызывают (они не записаны в тренировку). Правка сохранённой тренировки спрашивает всегда: изменённый черновик нельзя отличить от нетронутой копии.

**REQ02.** Корень — в `workflow.css` три старых блока `.workout-undo` с `position: sticky; top: sat+8; z-index: 15` под шапкой (z-index 20). Блоки удалены; панель `position: fixed` над таймером отдыха, класс `has-undo` добавляет отступ экрану. Видимый текст «Отменить», `aria-label` «Отменить удаление» — совместимо с прежними тестами. Работает и для убранного упражнения («Упражнение убрано»).

**REQ03.** На ≤640px `.workout-athletic :is(.sets-header,.set-row)` давал колонке «Прошлый» 44px. Новая сетка строки + `wrapSafe()` (мягкие переносы в тексте прошлого подхода) + `overflow-wrap`.

**REQ04.** Новый `src/lib/numberField.ts` (`selectOnFocus`, `trimLeadingZeros`) и `src/domain/SetPropagation.ts`. Протяжка по строкам ниже без нового поля в данных: следуют строки `i>index`, не отмеченные, того же вида (рабочий/разминка), у которых поле равно **старому** значению правимой строки; правка уже отмеченной строки никого не трогает. Работает только при вводе с клавиатуры; кнопки шагов и «подставить прошлый» меняют одну строку (см. изменение `design.spec`). Поля: вес, повторы, RIR, помощь, длительность.

**REQ05.** `WeeklyActivityBar`: склонения («тренировка/тренировки/тренировок», «подход/подхода/подходов»); «сетов» → «подходов» в `DeloadModal` (2 места) и сводке. Недельная сводка: «зачтено зонам» + пояснение `.week-summary-note` — методика засчитывает один подход всем нагружаемым зонам (поэтому «8 / 80» при 4 подходах корректно, формулы не менялись).

**REQ06.** `.resume-pill` скрыта на «Сегодня»; на остальных экранах `app-shell.has-resume` даёт `padding-bottom` под кнопку (+160px), так что последние строки «Прогресса» не перекрыты. Тост «Тренировка сохранена».

**REQ07.** Деталь истории: упражнения и подходы первыми, сводка/выводы — в `detail-insights`, Apple Health ниже. Подзаголовок упражнения собирается из частей (`recordingNote`, тренажёр/заметка, стороны) без обрывков; для штанги подпись «кг» вместо «кг общего веса», полная фраза — `recordingSentence`.
Оговорка по Apple Health: прямого подключения часов в браузере нет, но есть реальный импорт из файла (покрыт e2e) — поэтому панель не удалена. Убрано ложное утверждение, заголовок «Apple Watch» показывается только при данных (`no-data`), в режиме чтения без данных панель не рендерится.

**REQ08.** Убран постоянный блок «Контекст подхода» под каждой строкой; контекст открывается кнопкой в панели подхода (`.set-context-toggle`, после шагов веса в DOM, визуально справа сверху); свёрнутые блоки объединены (`.exercise-extras`); кнопка «Разминка» в одном ряду с «Подход» (`aria-label` «Добавить 3 разминочных»); сжаты поля и dock; шапка сворачивается через отрицательный `top` (`--bar-collapse`, ResizeObserver) без изменения высоты потока, только ≤640px. Критерии теста: ≥5 строк, шаг строки ≤85px, карточка ≤850px.

**REQ09.** `ExerciseLibrary`: `curatedTotal` через `useMemo` — число на вкладке «Основные» берётся из того же набора, что рисуются карточки.

**REQ10.** `AccountProfileForm`: ответ сервера сверяется с введённым весом; при несовпадении ошибка, а не «Профиль сохранён». `App`: тосты с тоном (`ok`/`warn`, `TriangleAlert`), при завершении — только «Тренировка сохранена». Свотчи цветов: подпись целиком (`athletic.css`). «Изменение веса» при ≤1 точке показывает «—». Сравнение в «Силе»: «Сравниваются только записи одной версии каталога и одного правила записи.»

**REQ11.** Удалён эффект `[journal]`, перезаписывавший поле после догрузки журнала; значение берётся из `FormData` (то, что человек видит), `massDirty` защищает набранное. Подробнее — в рисках.

## Риски и оговорки

1. **REQ11: тест на базе не красный.** На старом коде e2e-сценарий проходит, т.е. моя подстановка с задержкой журнала воспроизводит гонку не гарантированно. Исправление (удаление эффекта `[journal]`, значение из `FormData`, сверка ответа сервера) логически обосновано, но регрессию тест ловит слабо.
2. **iOS Safari: select-on-tap не проверен на реальном устройстве** (проверялось в Chromium-эмуляции 390×844 / 360×800). `onMouseUp.preventDefault` — известный приём, но поведение iOS может отличаться.
3. **REQ08, 360×800:** запас по «≥5 строк» мал (~1px после подрезки dock); изменения шрифта/системного масштаба могут его съесть. Проверено для упражнения 2×3 подхода.
4. Схлопывание шапки работает только ≤640px.
5. Отмена без вопроса при введённых, но не отмеченных значениях — осознанное решение (см. REQ01), его стоит подтвердить владельцу продукта.
6. Остался мёртвый CSS от удалённых блоков (`.set-context`, `.warmup-scaffold` и т.п.) — не удалял, чтобы не рисковать каскадом из четырёх файлов.
7. Протяжка значений не имеет отдельного поля «тронуто» (сравнение с прежним значением): если вручную набрать в нижней строке то же число, что стояло в правимой, оно будет заменено вместе с остальными. Намеренный компромисс ради отсутствия изменений формата данных.
8. Данные, экспорт и формулы статистики не менялись.
