## QA-R03-01 — офлайн-запуск сразу после первого входа

## QA-R03-02 — запуск тренировки из программы
Решение: **план программы — подсказка, а не введённое значение.**
- `TrainingProgram.start()`: подход N берётся из «Прошлого» (как «Повторить прошлые»), RIR — из прошлого подхода или пусто (раньше из плана оставался RIR 2). Без истории `reps = 0`, `rir = null`; вес из плана остаётся (он явно подписан в редакторе, REQ07). Исключения, где значение — правило программы, а не догадка: разгрузочная неделя (`deloadRir`) и шаг двойной прогрессии (`range.min` с `progressionNote`).
- План остаётся виден: у упражнения без истории `repMin/repMax` = диапазон плана, и плейсхолдер поля повторов (серый) показывает его (`WorkoutView`: прошлый результат → диапазон плана → «—»; прежнего выдуманного «10» нет). Если ✓ нажат без ввода, REQ01 не даёт отметить подход («Повторы не введены»).

Если расхождение повторится при чистом состоянии — нужен точный набор данных.
- Тесты: unit (8/8/7, RIR пусто, без истории пусто + подсказка, ✓ заблокирована), e2e «из программы». Изменены старые тесты программы: helper `performed` теперь вводит повторы, а тест диапазона «lateral» ждёт пустые повторы с подсказкой.

## QA-R03-03 — выход и данные на устройстве
Что хранится офлайн: (1) Cache Storage `tyaga-shell-*` — **только файлы приложения** (HTML, JS, CSS, шрифты, иконка), ни одного ответа `/api`; (2) localStorage: `tyaga-offline:session` (профиль), `tyaga-offline:data:<id>` (журнал, настройки, программы), `tyaga-draft-account:<id>` (черновик тренировки), `tyaga-bodyweight-*:<id>`, `tyaga-last-import:<id>`, `tyaga-import-run:<hash>`, устаревший `tyaga-draft-v1`. Данные не шифруются (скрипт на том же origin прочитает их — как любой localStorage); поэтому они стираются при выходе.
- `src/lib/deviceAccountData.ts`: `wipe()` — при выходе удаляет **все** `tyaga-*` кроме `tyaga-cloud` (ключ Android-сборки, не веб-аккаунта); оформление (`tyaga_theme_accent`) и звук (`tyaga_sound_muted`) личными не считаются и остаются. `purgeOthers(id)` — при входе стираются per-account ключи прежних аккаунтов (чужой черновик, журнал веса, копия данных); свои не трогаются. Вызывается в `AccountGate` при выходе (дважды: сразу и после размонтирования приложения), при входе/регистрации и при обновлении сессии.
- Решение, о котором нужно знать: **незавершённая тренировка при выходе стирается** (черновик — данные аккаунта). Подтверждения «в тренировке есть несохранённое» перед выходом нет.
- Cache Storage при выходе не трогается — в нём нет данных аккаунта (проверено в e2e: ни одной записи `/api`).
- Тесты: unit (`wipe`/`purgeOthers`, недоступное хранилище), e2e «выход»: после выхода нет ни одного `tyaga-*`, тема осталась, в Cache Storage нет `/api`; вход под другим аккаунтом — нет ключей прежнего, нет «Продолжить тренировку».

## R03-REQ04 по букве ТЗ — очередь отправки завершённой тренировки
**Проверка идемпотентности по коду** (`server/index.ts`, `PUT /api/workouts`): запись по `id` — upsert. При `revision = 0` это `INSERT … ON CONFLICT(id) DO UPDATE … WHERE owner совпадает AND revision = 0`; если строка уже есть, сервер сравнивает содержимое и **возвращает существующую запись** (тот же payload — не дубль и не новая ревизия), другое содержимое → 409, чужой владелец → 403. Значит повторная отправка того же payload безопасна, в том числе после «ответ потерян после записи». Серверный код менять не пришлось.

**Что сделано**
- `src/domain/PendingWorkouts.ts` (домен, без React): очередь в `localStorage` под ключом `tyaga-pending-workouts:<accountId>` (привязка к аккаунту). `add/remove/fail/clearError/list`, `merge(stored, queued)` — как тренировка из очереди показывается в истории (серверная версия побеждает, только если её ревизия **новее**, — случай потерянного ответа; ещё не отправленная правка с той же ревизией показывается вместо серверной), `isRetryable(e)` — сеть/таймаут (ошибка без `status`) и 5xx; `needsSignIn(e)` — 401. В очередь кладётся **ровно тот payload, который отправлялся** (длительность заморожена до отправки, как и раньше).
- `src/hooks/usePendingWorkouts.ts`: состояние очереди и `flush()`. Авто-отправка: событие `online`, возврат в приложение (`visibilitychange`), следующая успешная загрузка данных (`App.load`) и раз в 30 с, пока очередь не пуста. Один проход одновременно (`busy`) — триггеры не умножают запросы. 5xx/сеть — остановка прохода, повтор по следующему триггеру; 401 — ждёт нового входа, ошибкой не считается; другой 4xx/409 — тренировка **остаётся в очереди** с текстом ошибки и больше молча не повторяется, пока человек не нажмёт «Отправить сейчас».
- `App.tsx`:
  - «Завершить» → при обрыве связи/5xx тренировка кладётся в очередь, черновик **убирается** (ключ черновика стирается сразу, до эффекта), открывается «История», тост «Нет связи: тренировка сохранена на устройстве и ждёт отправки. Уйдёт сама, когда появится связь.». Если хранилище не приняло запись, всё остаётся как раньше (черновик + ошибка) — данные не теряются. Отказ сервера (4xx/409) при самом «Завершить» ведёт себя как раньше: диалог конфликта/ошибка, черновик цел.
  - Очередь видна в истории и на «Сегодня» (список недавних): метка **«Ждёт отправки»** у тренировки; баннер «Ждёт отправки: N …» с кнопкой «Отправить сейчас» (при отказе сервера баннер красный: «Сервер не принял: <причина>. Тренировка осталась на устройстве.»). Тренировки из очереди входят в статистику экрана как обычные.
  - Ожидающую тренировку нельзя править до отправки (тост «Тренировка ещё не отправлена…»); удалить можно — она снимается с очереди без запроса `DELETE`.
  - Офлайн-копия данных (`tyaga-offline:data`) хранит только серверный журнал, без очереди.
- Очередь стирается при выходе (`deviceAccountData.wipe()` стирает все `tyaga-*`) и при входе другого аккаунта (`purgeOthers`: префикс `tyaga-pending-workouts:` добавлен в per-account список) — QA-R03-03 не нарушен, тест на это есть.

## Риски и ограничения (Доработка 2)
- Тренировка, завершённая без связи, **не** повторяет побочные эффекты онлайна: итог для комнаты «Вместе» и общий итог встречи («Напарники») не отправляются из очереди — только запись в журнал. Если нужна отправка итога встречи после очереди, это отдельная доработка.
- Конфликт версий при отправке из очереди (409) не имеет экрана выбора «моя/серверная версия»: тренировка остаётся на устройстве с понятной ошибкой, данные не теряются; разбор — вручную (правка недоступна, пока запись ожидает; удалить можно).
- Очередь лежит в `localStorage` не зашифрованной, как и остальное личное (см. QA-R03-03); при переполнении хранилища «Завершить» сохраняет прежнее поведение (черновик + ошибка).
- Правка уже сохранённой тренировки без связи тоже встаёт в очередь (с её ревизией); если за это время она изменилась на другом устройстве, отправка вернёт 409 → см. выше.
- Проверен только Chromium; реального отключения сети на устройстве не было — связь эмулируется отказом запроса и событием `online`.
