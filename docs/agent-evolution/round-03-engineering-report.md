## По требованиям

### R03-REQ01 — подход без веса не считается молча
- `src/domain/SetCompleteness.ts`: `missing(exercise, set)` → `"weight"` там, где вес внешний обязателен (штанга, гантели «на руку», стек тренажёра; не время, не вес тела, не помощь), либо `"reps"`, если повторов < 1. Тексты: «Вес не введён — подход без веса не считается. Введи вес и отметь ещё раз.» / «Повторы не введены…».
- `WorkoutView.tsx`: ✓ у неполного подхода **не ставит зелёную отметку**, фокус уходит в недостающее поле, под строкой появляется `.set-hint` (`role="alert"`). После ввода веса и повторов одно касание ✓ записывает подход. Подход без отметки в рабочие/тоннаж/мышцы не попадает (как и раньше).
- `WorkoutSession.withoutUnperformed()`: невыполненные строки без повторов внутри выполненного упражнения не уходят в журнал (сервер требует повторы ≥ 1) — иначе «Завершить» ловило бы 400 из-за пустых строк.
- Решение: вместо отдельной пометки «без веса» подход просто не отмечается — это проще и не создаёт третьего состояния подхода.
- Тесты: `round-03.test.ts` (правила, пустые строки, Epley 100×8 = 126,7 не изменился), e2e «✓ без веса или повторов…» (в журнале ровно один выполненный подход 60×8).

Заготовки программ и тестовые фикстуры сохраняют прежние 3×10, RIR 2 (`blank = false` по умолчанию), чтобы не ломать план и ~20 файлов тестов.

Три ✓ подряд пишут 8, 8, 7 как в «Прошлом».
- Известное изменение поведения: раньше все подходы брали «финальный рабочий» подход прошлого раза, теперь — подход N; тест `model.test.ts` обновлён.

### R03-REQ04 — запуск без сети
- **Оболочка и каталог:** `scripts/serviceWorkerPlugin.ts` (подключён в `vite.config.ts`, не для `--mode device`) пишет `dist/client/sw.js` с версией = хэш состава сборки. Предзагрузка — все файлы сборки, кроме `vision_*`/`.wasm` (модель анализа техники ~22 МБ кэшируется при первом использовании). Навигация: сеть с таймаутом 4 с → иначе закэшированный `/`; `/assets/*`, иконка, манифест — сначала кэш; **`/api/*` и `/sw.js` сервис-воркер не трогает**. Новая версия: новый `sw.js` ставится сам (`skipWaiting` + `clients.claim`), старые кэши `tyaga-shell-*` удаляются при активации; проверка обновления — при каждой загрузке (`updateViaCache: "none"`). Регистрация в `src/main.tsx` только в production и не в Android-сборке. Файл `sw.js` — статический ассет Worker'а (`run_worker_first` только `/api/*`), отдельного маршрута не нужно.
- **Данные:** `src/lib/offlineSnapshot.ts` — копия профиля сессии и последнего успешного ответа (`workouts`, `settings`, `product`) в localStorage; `AccountGate` без сети (не отказ сервера — различаем `ApiError`) открывает кэшированный профиль, `App` показывает копию с баннером «Нет связи… Обновить»; копия обновляется вслед за журналом и стирается при выходе из аккаунта. Событие `online` само перезагружает данные.
- **Запись подхода:** черновик и так жил в localStorage — подход переживает перезагрузку без сети.
- **Playwright:** по умолчанию `serviceWorkers: "block"` (e2e, dev и офлайн-сценарий каталога раунда 2 не затронуты); сценарий офлайна включает его сам.
- e2e «запуск без сети»: первый вход онлайн → SW готов, кэш `tyaga-shell-*` заполнен → сеть отключена (`context.setOffline`, `/api` обрывается) → перезагрузка открывает «Сегодня», видны «Программы» и «История» (1 тренировка) → «Начать тренировку», ✓, перезагрузка без сети, «Продолжить тренировку» — подход на месте → сеть вернулась → баннер сам исчезает → «Завершить» уходит `PUT /api/workouts`.
- **Оговорки (честно):**
  1. «Завершить» без сети не работает: сохранение — запрос к серверу, очереди записи нет. Тренировка остаётся черновиком на устройстве; после возврата сети нужно один раз нажать «Завершить». Автоматической отправки «в фоне» нет.
  2. Проверено только Chromium + `vite preview`; на настоящем Cloudflare, в Safari/iOS и в установленном PWA — нет.
  3. Офлайн-копия — для чтения и черновика: правки программ/настроек без сети не поддерживаются.
  4. После деплоя вкладка со старой сборкой может не докачать ленивый фрагмент прежней версии (хэши имён меняются) — перезагрузка решает; общая особенность SPA, теперь с `skipWaiting`.
  5. Анализ техники по видео (wasm) офлайн доступен только если им пользовались онлайн.
