## Подтверждённые дефекты на `cb96307`

**QA-R02-01 · высокая/блокер · R02-REQ02: частичный импорт без отмены и смешанная замена.** Чистая собственная D1 `.wrangler/agent-evolution-qa-r2-fault-fresh`, локальный Worker `:8898`, Chromium mobile 360×800, подлинный Strong CSV (21 сессия, 175 подходов). UI показал «Уже сохранено 5 сессий…»; баннер «Отменить импорт» отсутствовал (`0`). После повторного запуска UI показал «добавлено 16, заменено 5». Ни одна из двух операций не атомарна на уровне файла; серверный `D1 batch` ограничен одним пакетом. ### Оценка лимита «30 тренировок / 450 КБ»

- **450 КБ не ограничивает.** Сериализованное тело `POST /api/import` для эталона: 17 987 Б на 21 тренировку = **≈ 857 Б/тренировка**; в 450 КБ влезает ≈ **525 тренировок**; 156 тренировок ≈ 134 КБ, 200 ≈ 171 КБ ([`limit.log`](../../artifacts/agent-evolution/qa/r02-recheck/limit.log)). Ограничивает именно **счётчик 30** (клиент и сервер, плюс ≤ 30 разных вариантов).
- **30 хватает только на ≈ 2–3 месяца.** Эталон из REQ02 — 21 тренировка за 8 недель (≈ 2,6/нед.), т. е. 30 ≈ 11 недель. Для самого сценария «поправить выбор после импорта» тестового файла лимит достаточен (REQ02 в ТЗ написан на нём). Но пользователь из ТЗ «приходит с годом записей»: при 3–4 тренировках в неделю годовая история — ориентировочно **150–210 тренировок** (≈ 5–7 файлов по 30; при 5/нед. — ≈ 260). Strong выгружает всю историю одним CSV, так что реальный годовой экспорт **целиком отклоняется**. Число тренировок в год — моя арифметика от частоты, не измерение по чужим данным. Лимит в 30 различных вариантов упражнений тоже реален для года разнообразной программы (мой вывод, не замер).
- **Вывод:** для REQ02 на эталонном файле достаточно; для «настоящего Strong-экспорта за год» **не достаточно**, это известная и подтверждённая живьём граница (QA-R02-06). Нужен chunked staging/finalize (по тем же receipt-таблицам) либо авторазбиение клиентом на несколько run'ов с общим откатом.

### Что не проверено

Два аккаунта и межаккаунтная изоляция (локальный entry — один owner), cloud-entry, правка импортированной тренировки через UI с последующим undo, устаревшая вкладка с прежним undo, Android-панель выгрузки версий `/api/sync/recovery` в интерфейсе, JSON-экспорт/импорт «Тяга», Hevy/FitNotes-файлы, `agent-*.spec.ts`, реальное устройство. PASS по ним не выставляется.
