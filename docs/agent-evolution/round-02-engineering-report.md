### R02-REQ02 — исправление импорта
- **Замена при повторном импорте** (по умолчанию включена, галочка в окне): `POST /api/import` принимает `replace: true`. Идентификатор тренировки детерминирован от `sourceKey`, поэтому раньше повтор пропускался. Теперь сервер удаляет и записывает заново **только** тренировки с префиксом `import:` и `revision = 1` (то есть не правленные пользователем) в том же атомарном `D1 batch`; правленные остаются и считаются в `kept` («твои правки сохранены: N»). Ответ дополнен `replaced`, `kept`, `addedIds`, `replaceable` (dry-run) — поля только добавлены, старые клиенты работают как раньше. Без флага поведение прежнее.
- **«Отменить импорт»** без серверной миграции: `ImportUndo` хранит на устройстве (по аккаунту) id, которые записал последний импорт; в «Истории» баннер «Импорт: добавлено N · Отменить импорт» → подтверждение «Убрать N» (итого: файл → предпросмотр → «Импортировать»; ошибку исправляют двумя касаниями: «Отменить импорт» → «Убрать»). Удаляются только неправленные (`revision 1`) и ещё существующие; правленные/удалённые остаются и называются в тосте. Баннер переживает перезагрузку, «Скрыть» убирает его.
- Тост импорта теперь честный: «добавлено A, заменено R, пропущено S, твои правки сохранены: K».
- Файлы: `server/HistoryImportService.ts`, `src/services/ImportService.ts`, `src/domain/ImportUndo.ts`, `src/App.tsx`.
- Тесты: `tests/import-replace-api.test.ts` (Miniflare: замена, идемпотентность, правка сохраняется, `addedIds` → удаление → повторный импорт), `tests/import-undo.test.ts`, e2e.

### R02-REQ04 — офлайн
Первопричина: файл каталога — отдельный lazy-чанк, который при отсутствии сети не загружался, `React.lazy` запоминал отказ и ронял всё дерево («чёрный экран»). Исправлено в три слоя:
1. **Предзагрузка**: при старте приложения (idle, `timeout 2 с`) докачиваются `ExerciseLibrary` и `ProgramsScreen`, плюс `preload` в `WorkoutView` — после первой загрузки «Добавить упражнение» открывается без сети.
2. **Граница отказа**: `lazyChunk`/`chunks.tsx` — все lazy-экраны вместо падения показывают «Каталог не загрузился / Нет связи … / Повторить». Остальное приложение и тренировка на месте.
3. **«Повторить»**: опытным путём выяснено, что Chromium помнит неудачный `import()` до конца жизни страницы, поэтому повторный `import()` не идёт в сеть. «Повторить» поэтому: пробует загрузить; если связь есть, а файл всё равно «не загрузился» — перезагружает страницу (черновик тренировки хранится на устройстве и возвращается: «Продолжить тренировку»); без связи страница **не** перезагружается (иначе пропало бы и само приложение) — остаётся сообщение «подключись к сети и нажми «Повторить»».
- Проверка реальным отключением сети в Chromium (`context.setOffline`): `tests/e2e/round-02.spec.ts` — (а) после докачки с отключённой сетью каталог открывается, в консоли нет ошибки загрузки модуля, `pageerror` нет; (б) файл не докачан + сеть выключена → сообщение с «Повторить», тренировка на месте, офлайн-«Повторить» не перезагружает страницу, после возврата сети — перезагрузка и каталог открывается. Прогнано 8 раз подряд на холодном стенде — 8/8.

## Риски и решения для лида
1. **Новые id в v3** (`deadlift-bar`, `row-bent-bar`, `ohp-bar`) — аддитивны, но тренировки с ними не откроются в старом клиенте/сервере: выкатывать клиент и воркер вместе.
2. **Отмена после замены** не возвращает прежние (буквальные) записи — это сказано в баннере. Прежние «свои» упражнения из старого импорта остаются в личном каталоге (лимит 200); чистку можно предложить отдельно.
3. **Замена по умолчанию включена** и трогает только `import:`-тренировки с `revision 1`; правленное не меняется. Если захочется осторожнее — галочку можно сделать выключенной по умолчанию.
4. **Chromium и неудачный `import()`**: «Повторить» при наличии сети перезагружает страницу. Данные тренировки сохраняются, но открытое окно «Добавить упражнение» закрывается.
5. **Красная проверка e2e на базе** не выполнена (запуск копии HEAD в scratchpad отклонён). Unit/API-тесты нового кода на базе красные по определению (нет модулей), e2e — нет.
6. На мобильных `Select searchable` при открытии может поднять клавиатуру — не проверялось на устройстве.
7. Один раз в общем прогоне упал `workout.spec` «personal timed exercises…» (зависимость от состояния общего стенда); в изоляции и в итоговом прогоне зелёный.

## Доработка QA

После независимого QA HIGH/BLOCKER серверный импорт исправлен адресно:

### QA-R02-04 — тупик после «Убрать черновик»
Клиентский `runId` (`tyaga-import-run:<хэш файла>`) теперь сбрасывается двумя путями, оба в `src/services/ImportService.ts`:
1. `undo()` (то же действие, что «Убрать черновик» и «Отменить импорт») после успеха забывает **все** ключи, которые указывают на этот `runId`;
2. если сервер всё же ответил «уже отменён» (ответ об отмене потерялся, ключ остался), `import()` один раз сам заводит новый `runId` и повторяет операцию. Серверное правило не менялось: отменённый run по-прежнему нельзя «оживить» старым токеном.

### QA-R02-06 — годовой экспорт (210+ тренировок)

### Остаточные ограничения (честно)
1. **Лимиты Cloudflare D1 не проверены.** Тесты идут на Miniflare/SQLite. Не подтверждено живьём, что одна `batch` отмены на 210 тренировок (до ~630 операторов при замене) и один оператор публикации на 210 строк укладываются в лимиты продуктовой D1 и в лимит подзапросов Worker; поэтому дал выигрыш через пакетное чтение, но сама атомарная публикация и отмена остаются одним пакетом. Перед релизом стоит пробный годовой импорт на тестовом облачном стенде (я его не делал: удалённая D1 запрещена).
2. **Верхний предел** — 60 частей (1800 тренировок) и общий лимит 200 личных упражнений на аккаунт; больший файл отклоняется с понятным текстом. Деление на части идёт по порядку файла.
3. **Resume** — только тем же файлом с теми же ответами в том же браузере (`runId` в localStorage). Если ключ потерян, сервер хранит черновик (виден, отменяется), а повтор заводит новую операцию и заново кладёт все части; старый черновик нужно убрать кнопкой.
4. **Частично оборванный run не публикуется** — и такой он виден только как «Импорт не завершён · N» без разбивки по частям.
5. **Отмена замены** по-прежнему не возвращает записи, правленные пользователем (они остаются), а «замену на замену» (цепочка) отменяет только последняя операция.
6. Сервер принимает не более 30 тренировок за запрос; старые клиенты ≥31 тренировки по-прежнему получают отказ (только клиент с этим коммитом делит файл). Клиент и воркер выкатывать вместе.
7. Не проверено: живой браузерный годовой импорт через UI на реальном воркере (UI-путь покрыт e2e на подставных ответах для ≤30 и серверными/клиентскими тестами для 210), два аккаунта живьём, Android.
8. N-3 (плашка «Вернуться к тренировке» поверх карточек на 360 px), N-4 (число касаний), N-6 (голые алиасы без «(Barbell)») — не менялись.
