## Что сделано

### QA-R11-01 (High) — первое касание в ведомом окне
- Причина: `pointerdown` делал окно основным, строка «открыта в другом окне» уходила из потока, вёрстка съезжала, и `click` попадал в соседнюю кнопку («+5» панели быстрой правки): вес выполненного подхода менялся молча.
- Теперь первое касание или нажатие мышью в ведомом окне **только** делает его основным. Остаток жеста (`pointerup`, `touchstart`/`touchend`, `mousedown`/`mouseup`, `click`, `dblclick`) глушится в capture-фазе `document` до React (`stopImmediatePropagation`; у `mousedown` и `click` ещё и `preventDefault`, так что фокус в «чужом» поле тоже не ставится). Глушение одноразовое: снимается после `click`, следующим `pointerdown` (новый жест) или через 3 с.
- Сообщение (тост): «Это окно стало основным — нажми ещё раз».
- Не глушатся: кнопка «Открыть здесь» (она сама делает окно основным; нажатие внутри строки `.draft-follower` исключено), клавиатура (`keydown`, `focusin` из Tab, `input`): окно становится основным, символ остаётся в поле. Проверено: набор «87.5» с клавиатуры в чужом поле целиком попадает в поле и в черновик.
- Вёрстка под пальцем: глушение делает прыжок безопасным — действие не выполняется; второе нажатие приходит уже в новую вёрстку, которую человек видит.
- Файлы: `src/lib/useDraftTabs.ts`, `src/lib/draftTabs.ts` (`TOUCH_NOTE`).
- Тесты (e2e, `round-11.spec.ts`): касание (`tap`) и мышь на 390/360/320 — после первого нажатия ни вес, ни повторы, ни ✓ не изменились, тост виден, второе срабатывает; «Открыть здесь» без глушения; ввод с клавиатуры.

### QA-R11-02 (Medium) — «Дублировать вкладку»
- Идентификатор окна теперь константа модуля на загрузку документа (не `sessionStorage`): копия `sessionStorage` при дублировании вкладки больше не даёт двух окон с одним id.
- Побочное, о чём просили: после перезагрузки окно получает новый id и, пока идёт опрос «кто здесь» по `BroadcastChannel` (≤ 400 мс), строку «открыта в другом окне» не показывает; нет ответа — окно само становится основным, есть — строка появляется сразу после ответа. Пока опроса нет, вёрстка не сдвигается; нажатие в этот момент делает окно основным без глушения (строки нет, прыгать нечему).
- Без `BroadcastChannel` опрашивать некого: окно остаётся ведомым и становится основным по нажатию или набору текста; молчаливой потери нет, но перезагруженное единственное окно потребует одного нажатия (допустимо по вашему условию).
- Тесты: e2e с копией всего `sessionStorage` первой страницы во вторую до загрузки (init-скрипт) — подходы 1–3 отмечены в разных окнах, ни один не пропал, ведомое окно ровно одно; e2e на перезагрузку единственного окна (`MutationObserver` фиксирует, что строка ни разу не появилась).

### QA-R11-06 (Low) — гонка «Начать»
- Обработчик `storage` брал `e.newValue`, а событие чужой записи могло прийти после следующей своей. Теперь значение перечитывается из `localStorage` по событию; исключение — удаление (`newValue === null`): там нужен `oldValue`, чтобы понять, чей черновик убрали.

### QA-R11-05 (Low) — копия дня Лейда: 75 в поле, а старт с 90 × 5
- Что происходит: `TrainingProgram.start` для обычной программы (а копия Лейда — обычная, `periodization` сброшена) берёт вес подхода из последней тренировки того же упражнения (`reference`): `base = ref.weight`, вес из программы — `s.weight` — используется только когда истории нет. В копии `sets` лифта заполнены весами плана недели (`liftSets`), поэтому в поле «Вес» 75, а старт идёт с веса истории. `weightHints` это знает (`source: "history"`).
- Теперь подпись «Начнёшь с веса из истории: N кг» у упражнения копии Лейда скрыта только когда `N` совпадает с весом в поле; если различается — показывается с реальным числом (это и объясняет расхождение). У упражнений без веса — как раньше.
- Тест: e2e — история жима 70 × 8 против 75 в поле: подпись «70 кг» есть; история 75 × 1: подписи нет. Прежнее e2e REQ04/2 обновлено под это правило (смысл «подпись не врёт» сохранён).
- Файл: `src/components/ProgramsScreen.tsx`.

### QA-R11-07 (Low, не R11) — журнал веса между окнами
- Слушатель `storage` в `BodyweightContext` реагировал на любой ключ и всегда запускал `reload()` и `sync()`. Теперь: только запись самого журнала (`BodyweightJournal.watches(key)`), а отправка — только если в журнале есть неотправленное (`pendingCount > 0`). Одного фильтра по ключу мало: журнал пишет в тот же ключ после каждой синхронизации (`lastSyncedAt`), и окна всё равно перебрасывали бы друг другу эту запись.
- Тест: e2e в двух окнах с видимым `visibilityState`: новый замер из одного окна доходит до другого; число записей `tyaga-bodyweight-sync` за 6 с после этого < 12. Оговорка: цикл на моках у меня не воспроизвёлся ни на старом, ни на новом коде (за 6 с — 0 записей), поэтому тест проверяет доставку замера и верхнюю границу записей, но не падает на старом коде; полностью воспроизвести QA-цикл в стенде с моками не удалось.
