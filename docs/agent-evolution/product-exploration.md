## Возможности и ограничения — только из документации

Ниже — ориентиры для исследования, **не наблюдения UI**:

- Есть старт/продолжение тренировки, вес/повторы/RIR, рабочие и разминочные подходы, отметка выполнения, отдых, черновик, отмена удаления, история, редактирование и повтор. Enter должен переводить фокус к следующему видимому числовому полю; дополнительные действия отделены от основных ([ежедневная работа](<../daily-workflow.md#L23-L27>)).
- Программы имеют наборы подходов, начальные веса, диапазоны, дни недели, отдых и предложения двойной прогрессии. Изменение — предложение, а не молчаливое переписывание истории ([сценарии 1.3](<../product-v1.3.md#L3-L15>), [сценарии 1.5](<../product-v1.5.md#L9-L30>)).
- «Прогресс» объединяет Обзор / Сила / Мышцы / Вес тела. Периоды, неизвестные значения, прямые/помогающие/стабилизирующие участия и смысл e1RM должны читаться без физиологических обещаний ([ежедневная работа](<../daily-workflow.md#L17-L21>), [методика](<../methodology.md>)).
- Свободный вес, одна/две гантели, стороны, собственный вес, помощь и стек тренажёра имеют разные правила. Машины и явно записанные стороны/ROM разделяют сопоставимые серии; тоннаж не является стимулом мышц ([методика](<../methodology.md#L35-L51>), [единая аналитика](<../analytics-and-technique.md#L15-L33>)).
- Данные сохраняются с версиями; конфликт двух устройств не должен незаметно перезаписывать чужое изменение. Недоступное хранилище/сеть и восстановление копии имеют явные границы ([методика](<../methodology.md#L71-L79>), [надёжность](<../reliability-and-challenges.md#L13-L21>)).
- Установка на домашний экран не обещает полного offline web-режима; native Android-сигналы, Apple Health и видео имеют ограничения, которые нельзя объявлять проверенными эмуляцией Chromium ([README](<../../README.md#L7-L10>), [сценарии 1.4](<../product-v1.4.md#L78-L104>), [надёжность](<../reliability-and-challenges.md#L23-L31>), [видео](<../analytics-and-technique.md#L41-L55>)).
- Нижняя мобильная навигация включает программы и друзей; комнаты/социальные действия требуют явного участия и имеют границы приватности ([напарники и комнаты](<../friends.md>)). Это вторичный сценарий, не повод добавлять ещё одну функцию без пользовательской необходимости.

### Основное исследование: как я действительно тренируюсь

- Начать с **390×844, touch/mobile Chromium**; повторить критический путь на **360×800**. Иногда открыть desktop 1440×1080 для Tab/Enter/Escape. Явно задать locale и timezone в контексте и записать их в журнал действий.
- До создания данных осмотреть «Сегодня», нижнюю навигацию, доступ к программам/истории/прогрессу и пустые состояния. Записывать и удачные решения, и реальные затруднения.
- Начать обычную тренировку через видимую кнопку, найти знакомое упражнение, задать рабочие подходы. Проверить последовательный ввод цифр, изменение веса/повторов/RIR, касание отметки, отдых, переход к следующему подходу и добавление подхода. `.fill()` подходит для setup, но не доказывает удобство посимвольного ввода; для этой оценки нужны реальные последовательные клавиши/касания.
- При фактическом появлении дополнительных действий изучить, не нужно ли их открывать ради каждого основного подхода. Не выбирать селектор только потому, что он есть в старом E2E: сначала сопоставить текущую видимую подпись/роль.
- Сворачивать черновик, уходить в другой раздел, делать reload, возвращаться и сравнивать введённые значения. Отдельно удалить собственный тестовый подход/упражнение, изменить оставшиеся записи и проверить отмену, в том числе после reload.
- Завершить тренировку, открыть её из истории и ещё раз после reload. Проверить реальные веса/повторы/стороны/разминку, редактирование и повтор. Затем создать следующую сопоставимую тренировку через UI и проверить доступность предыдущего результата; не обещать такое сравнение на пустой истории.
- Использовать небольшую собственную программу: увидеть подходы/диапазоны/отдых, изменить одно поле посимвольно, сохранить/reload/запустить. Сравнить новый черновик с тем, что программа обещала; не требовать переделки циклов по одному лишь чтению старой документации.
- После появившихся реальных данных открыть Обзор/Силу/Мышцы/Вес тела. Сначала объяснить себе, что означает каждый результат и период. Сопоставить значения с собственными записями; неизвестный RIR/масса/ROM не должны считаться известными без реального основания.
- Тренажёры, односторонние движения, разминка, импорт/экспорт и второе browser-устройство проверять по мере реальной необходимости. Сохранность можно дополнительно подтвердить другим чистым контекстом с UI-входом в тот же локальный аккаунт. Любая диагностика сети/контроль сохранённого JSON — дополнительное доказательство, не замена пользовательскому сценарию.
- Network/offline/lost-response сценарии допустимы только как явно маркированный отдельный эксперимент на своих локальных данных после gate. Отсутствие сети для полного cold-start web не объявлять новой регрессией известного ограничения.

### Evidence и честные выводы

Каждый запуск и самостоятельный шаг: фактическое время/URL/viewport/timezone, собственные тестовые данные, действие, видимый результат, ожидаемое значение и точный путь evidence. Сохранять viewport-снимок для reach/перекрытий и при необходимости full-page для контекста только после реального шага. Трассы/консоль/сетевые статусы — в своей области; журналы не должны содержать секреты.

Перед визуальным выводом действительно прочитать изображение. Если модель не принимает изображение, вызвать `modlens_read_image` **один раз на снимок/focus** и опираться на его evidence и uncertainty, не на догадку. Старые скриншоты разработчика не выдавать за свои.

Число касаний, переходов и размеры целей можно сообщать только после реального измерения с описанной методикой. Время автоматизации не равно скорости реального человека. Chromium mobile emulation не доказывает комфорт физического большого пальца, поведение iOS-клавиатуры, вибрацию или системные Android-уведомления. Непроверенное отметить явно.
