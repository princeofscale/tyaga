## 5. Что не удалось / ограничения

- Границу ошибок проверял на инструментированном бандле (подстановка броска в ответе сервера): настоящего падения компонента на продакшен-данных, кроме мусорных `routine` и `settings` из QA-R10-10, воспроизвести не удалось. Для вывода про «тело `JournalApp`» достаточно семантики React (граница — потомок), плюс реальный мусорный `routine` гасит приложение.
- Два сценария в `s36-plates2` (замена упражнения, суперсет) в первой версии скрипта имели неверные ожидания (ожидал 60×3 вместо 90/70/70 после «Повторить прошлые»; искал кнопку замены на гантельном упражнении). Перепроверил отдельным сценарием `s36c2-swap` (замена на штанговую альтернативу) — приложение работает верно; в итоги выше включены только подтверждённые.
- «Начать» программы без основного лифта проверял на цикле с удалённым приседом; в продакшене такой сценарий возможен только руками.
- Второй аккаунт на одном стенде невозможен (локальный режим — одна личность на БД); двухаккаунтные проверки шли на отдельных стендах.
- Прогон 14,8 мин ≈ заявленным 14,5 мин инженера.
