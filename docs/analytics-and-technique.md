# Единая аналитика, выполнение и видео

Новая реализация поверх методики 2. Старые тренировочные записи и каталоги 1–3 не переписываются.

## Факты и календарь

`AnalyticsFacts` — общий поток валидных завершённых подходов. По умолчанию он исключает разминку, будущие даты в часовом поясе аккаунта, повреждённые числа и повторяющиеся ID подходов. При нескольких копиях тренировки с одним ID используется самая новая ревизия, затем `updatedAt`; удалённые из неё подходы не восстанавливаются из старой копии. Источник остаётся неизменным. Разминку можно запросить отдельно; `includeFuture` и незавершённые подходы доступны только как явные опции для специальных инструментов.

Диагностика содержит число исключённых повреждённых подходов, дубликатов и неверных дат. Тоннаж не становится NaN из-за одного плохого значения. Серии, PR, силовые графики, недельные тренды, карта мышц, итоги сессии и разгрузка используют общий слой. Сохранённые агрегаты не создаются: редактирование даты и удаление подхода меняют результат следующего расчёта.

`calendarWeek(date)` возвращает понедельник–воскресенье. `trailingWindow(today, 7)` — сегодня и шесть предыдущих календарных дат. Тренды включают текущую и 11 предыдущих календарных недель; будущие тренировки не попадают ни в тренды, ни в рекорды, ни в streak. Отсутствующие недели не выдумывают тренировок. Граница считается по понедельнику, а не по ISO-номеру: неделя 53 и переход года не сталкиваются. В интерфейсе эти периоды имеют разные подписи.

`WorkoutReference` выбирает предыдущую завершённую работу того же варианта/контекста не позднее даты редактируемой тренировки. Повтор создаёт новый факт с текущей `ANALYSIS_VERSION`, сохраняя версию каталога и снимки каждого упражнения. Импорт собственной резервной копии сохраняет исходную версию анализа; это отличается от создания нового повтора.

## Модель и станция тренажёра

`machine_models` хранит неизменяемое описание модели: изготовитель, название, механизм и правило показания веса. `machine_instances` — станцию в конкретном зале, её стабильный ID, название, алиасы, справочные передаточные отношения и ревизию. Данные изолированы владельцем. При выборе станции журнал сохраняет `machineInstanceId` и снимок `machineSnapshot`.

Переименование станции не меняет ключ прогресса. Другая станция с тем же названием — другая серия. Алиасы помогают искать, но не объединяют аппараты автоматически. Архивирование убирает станцию из списка выбора и сохраняет старые снимки. Старые записи без ID продолжают сравниваться по `equipmentNote`; автоматического объединения неоднозначных старых пометок нет. Передаточные отношения не переводятся в мышечную силу.

Мышцы берутся из варианта упражнения, никогда из модели тренажёра. Общий показатель называется тоннажем свободных весов; машинные значения стека показываются отдельно внутри той же станции, варианта, стороны и выполнения. Они не прибавляются к общему тоннажу, как и собственный вес/помощь.

`0010_machines.sql` — добавочная миграция с индексами и триггерами репликации. Снимок Drizzle также обновлён. Станции и модели синхронизируются отдельно. Новый клиент объявляет `capabilities=machines-v1`; старые клиенты получают прежние типы документов с правильным продвижением курсора. Это не делает старый интерфейс способным редактировать новые поля — для новых функций нужен обновлённый клиент.

## Стороны и контекст выполнения

`ExecutionProfile` содержит ROM (`full`, `lengthened_partial`, `shortened_partial`, `custom`), хват, стойку, рукоять, угол скамьи/корпуса, начальный/конечный угол и темп. Пустое значение означает «неизвестно», а не «полная амплитуда».

Профиль задаётся для упражнения; подход может переопределить отдельные поля. `SetEntry.performedSides` переопределяет прежнее значение упражнения только для этого подхода. Старое `WorkoutExercise.performedSides` остаётся fallback для совместимости.

`ExecutionIdentity` разделяет серии прогресса по машине, стороне и явно записанному контексту. Одинаковый вес на разных станциях или при разном ROM не выдаётся за один непрерывный рекорд. Счётчик участия мышцы остаётся счётчиком подходов: метаданные не превращаются в коэффициенты роста. Суперсеты не умножают подходы; итоги показывают число групп и плотность записи, не физиологическую усталость.

Новые поля валидируются API и сохраняются в черновике, истории, программах, JSON-копии v5 и импорте. Копии v1–v4 также читаются. Импорт станций из снимков вместе с тренировками происходит в одной транзакции после проверки; dry-run не пишет данные.

## Версионируемая анатомическая интерпретация

`ExerciseTaxonomy` отделяет существующие семейства от конкретных вариантов каталога. `MuscleInvolvement` хранит роль, уверенность, тип основания, источники, контекст и ревизию модели. Региональные акценты груди вынесены в `data/muscle-involvement-v1.ts`; нет извлечения анатомии из слов названия. Новые entries сохраняют `muscleModelRevision: 1`; отсутствие поля в старой истории означает первую ревизию, а не автоматический переход на будущую модель. Явные роли в сохранённом каталоге имеют приоритет. Карточка показывает происхождение интерпретации.

Участие мышцы, правдоподобие анатомической гипотезы и индивидуальный эффект на гипертрофию — разные сведения. Мы считаем первое, сопровождаем второе источниками и не вычисляем третье по журналу. Научные основания: [биомеханика и недельный объём](biomechanics-and-volume.md).

## Видео на устройстве

Инструменты → «Анализ техники по видео». Поддерживается локальный файл до 3 минут и 300 МБ. MediaPipe Tasks Vision **0.10.35** закреплён в lockfile. JS/WASM поставляются с приложением; CPU-выполнение поддерживает SIMD и fallback без SIMD. Видео и кадры не отправляются на сервер. На первом анализе скачивается официальная модель Pose Landmarker Lite float16 v1; можно отменить загрузку или анализ. Модель повторно используется в открытой сессии.

Версия SDK выбрана после проверки сетевого поведения: последняя на момент разработки версия отправляла телеметрию, закреплённая версия проходит тест на отсутствие исходящих POST при анализе. Обновление SDK требует повторной проверки. [Google: локальная обработка](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/web/vision/README.md), [официальный Web API](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker/web_js).

Обрабатывается 5 кадров/с. Геометрия использует оценочные world landmarks и отбрасывает невидимые/недостоверные точки и вырожденные векторы. Показаны внутренние 3D-углы коленей, тазобедренных, локтей и плеч, число распознанных кадров и разность 5-го/95-го процентилей. Если надёжных кадров меньше пяти, показывается отсутствие данных, а не нулевой ROM. Искажения ракурса и одиночной камеры остаются; это не оценка сил мышц, риска травмы или качества техники. Из результата не выставляется автоматическая отметка «полная амплитуда» в журнале.

Отчёт с временным рядом можно скачать в JSON. В базу и синхронизацию сам видеофайл не попадает. В R&D экспорт можно сравнить с калиброванной таблицей OpenSim/OpenCap:

```sh
npx tsx scripts/validate-pose-reference.ts report.json reference.mot mapping.json
```

В mapping задаются имена координат, знак и нулевая точка — пример [pose-calibration.json](examples/pose-calibration.json) иллюстрирует формат, а не универсальную калибровку человека. Выводятся MAE/RMSE на пересекающихся временах; отсутствующие точки не заменяются нулём. OpenSim/OpenCap не добавлены в мобильный runtime и не запускают inverse dynamics по одиночному видео.

## Внешний контроль данных

wger остаётся источником поиска с прежним provenance и лицензиями. Дополнительный датасет можно привести к нормализованному формату с обязательными `sourceUrl` и `license`, затем сравнить:

```sh
npx tsx scripts/audit-exercise-data.ts docs/examples/muscle-crosscheck.json
```

Скрипт выводит различия direct/assistant и несопоставленные ID. Он не импортирует разметку автоматически и не объявляет внешний набор научной истиной. Новые варианты и коэффициенты требуют отдельного редакционного решения; код AGPL-проектов не копируется.

## Проверки

Golden-набор охватывает границы недель/года/DST, будущие даты, разминку и незавершённые подходы, ревизии/дубликаты/удаление, NaN/Infinity/отрицательные числа, повтор legacy, односторонние подходы, ROM, суперсеты, машинные ID, owner isolation, API/backup/import/sync. Существующие проверки сохраняют правила пары гантелей, собственного веса, помощи, duration и исторических каталогов.

```sh
npx tsc --noEmit
npm test
npm run build
npm run test:e2e:prepare
npm run test:e2e
```

Подготовка E2E загружает официальную модель и тестовый кадр только в игнорируемый `artifacts/models`, проверяя SHA-256. Браузерные тесты запускают настоящий WASM-детектор на пустом видео и на официальном кадре с человеком, а не подменяют ответ ML-модели.
