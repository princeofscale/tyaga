# Единый вес, полная копия, отдых и четыре недели вместе

Изменения продолжают PR #7. Production D1, сайт и опубликованный APK не обновлялись. Перед выпуском нужна добавочная миграция `0009_noisy_iron_lad.sql` после миграций прежних PR. Android-исходники следующей сборки используют `versionCode 4`, `versionName 1.5.0`; сохранённая на сайте пара APK/JSON остаётся прежней до отдельного выпуска.

## Вес и снимок тренировки

`BodyweightProvider` обслуживает один журнал аккаунта для профиля, экрана веса, новой тренировки и резервной копии. Профиль показывает последнее взвешивание; изменение массы в форме записывает замер за сегодняшний день, сохраняя заметку уже существующего замера. Форма имени, веса и часового пояса доступна сразу, подписи сохранения/выхода прежние.

Новые упражнения с собственным весом получают последний замер не позднее даты тренировки. Сохранённые тренировки и уже внесённые упражнения сохраняют свою массу: последующие взвешивания не меняют прошлые результаты. Повтор тренировки получает свежий снимок. Пока журнала ещё не было, прежняя масса профиля служит запасным значением. После удаления всех взвешиваний это значение не восстанавливается. На Android запасная масса другого подключённого аккаунта не подставляется; редакторы сбрасываются при смене облачного журнала.

Смена профиля не переименовывает владельца очереди. Прежние ключи веса остаются резервным источником миграции. Кэш и очередь по-прежнему записываются одним JSON-значением; короткие операции чтения/изменения защищены Web Locks между вкладками, если API доступен, и общей очередью внутри окна. HTTP-запросы выполняются без удержания блокировки. Перед подтверждением ответа перечитывается текущий кэш, поэтому более свежий локальный ввод сохраняется.

## Полная резервная копия v4

«Инструменты → Резервная копия» скачивает один JSON с сохранёнными тренировками и их снимками правил/массы, программами, личными упражнениями, избранным, ориентирами, взвешиваниями, целью, цветовой темой и открытыми полями профиля. Пароли, сессии, коды восстановления, email и социальные данные не экспортируются. Черновик активной тренировки остаётся отдельным экспортом, доступным на экране тренировки.

Прежняя кнопка «Экспорт JSON» в истории использует тот же полный формат. Экспорты v1–v3 продолжают читаться. При импорте видны сессии, подходы, программы, новые/совпавшие/различающиеся взвешивания и цель из файла. По умолчанию существующие замеры и цель сохраняются. Отдельный флаг разрешает взять значения из файла за совпадающие даты. Восстановление профиля и настроек требует отдельного выбора; учётные данные текущего аккаунта сохраняются.

Работающий импорт переносит программы/упражнения с прежним сопоставлением ID, пропускает повторные сессии и атомарно добавляет вес в локальную очередь. Повтор после прерывания безопасен. При недоступной сети очередь веса остаётся на устройстве, а реальный облачный конфликт требует отдельного выбора версии. Импорт не удаляет записи, отсутствующие в файле. Некорректные/будущие даты взвешиваний отсекаются до переноса.

Старый экспорт мог содержать движение каталога 3 на неизвестной машине. Такая сессия получает явную пометку `Не указан · импорт <дата> · <идентификатор>`: копия сохраняется, а разные неизвестные машины не объединяются в один ряд силы. Название блока можно уточнить при редактировании тренировки.

## Системный таймер отдыха Android

«Инструменты → Уведомления отдыха» включает функцию по действию пользователя. Android 13+ запрашивает уведомления; доступ к точным будильникам открывается отдельной кнопкой в системных настройках. Без точного разрешения используется обычный системный будильник, и интерфейс предупреждает о возможной задержке. В браузере сохраняется таймер открытого экрана; фоновые сигналы предоставляются приложением Android.

Локальный Capacitor-плагин хранит владельца, тренировку, срок и следующий подход, планирует `AlarmManager` и принимает сигнал через непубличный `BroadcastReceiver`. Обычная приостановка WebView и завершение процесса не требуют работающего JS. Уведомление «Отдых завершён» содержит `+30 с`; нажатие открывает текущую тренировку и фокусирует следующий подход. Действие старой/чужой тренировки не применяется к новому черновику. Пауза, завершение, отмена и выключение функции снимают будильник; старый сигнал после продления игнорируется.

При открытом экране тренировки системный сигнал подавляется, чтобы не дублировать звук интерфейса. На экране блокировки не выводятся веса, заметки и название упражнения. Принудительная остановка приложения, перезагрузка телефона и ограничения энергосбережения производителя подчиняются правилам Android; перезапуск приложения восстанавливает состояние таймера из черновика.

Android APK собирается, а Robolectric на API 35 проверяет планирование/отмену, уведомление, продление, устаревший сигнал и подавление дубля. Браузерный тест native-моста проверяет включение, отдельное разрешение точности, продление свёрнутого черновика и возврат к подходу. Физический телефон не использовался. Эмулятор не удалось запустить: его образ данных требовал 7,2 ГБ свободного места при доступных 4,9 ГБ на временном RAM-диске.

## Челлендж на четыре недели

Организатор выбирает понедельник текущей/ближайших четырёх недель, название, собственную цель и принятых напарников. Приглашённый отдельно принимает участие и выбирает 1–14 тренировок в неделю. Цель фиксируется при первом принятии; выход и повторное принятие не уменьшают её. Изменение обычной недельной цели команды не меняет условия начатого челленджа.

Для зачёта нужна сохранённая тренировка с выполненным рабочим подходом. Четыре окна по семь дней используют календарные даты журнала; будущие дни не засчитываются. Каждая недельная цель каждого атлета учитывается отдельно, поэтому лишние занятия одного участника не закрывают цель другого. Видны четыре недели, выполненные личные цели и лучшая серия; можно скачать SVG-карточку собственного результата. Карточка не содержит чужих имён и результатов.

`team_challenges` и `challenge_participants` — серверные социальные таблицы. API: GET/POST `/api/challenges`, PUT `/api/challenges/:id` с действиями accept/decline/cancel. Действующая сессия, Origin/JSON и идентификатор активного аккаунта проверяются. Список и действия требуют участия и текущей дружбы с организатором. До согласия чужие недельные показатели не раскрываются. После удаления дружбы доступ и видимость участника отзываются; сводки не передают названия тренировок, вес, подходы, заметки или email.

Лимиты: до 20 приглашённых и пяти активных челленджей организатора. Повтор создания не меняет приглашение; изменённые условия требуют нового ID. Отменяет только организатор после подтверждения. Челленджи загружаются отдельно от ленты/встреч, чтобы их запросы не увеличивали стоимость каждого обновления ленты.

## Верификация

Обязательные проверки: `npx tsc --noEmit`, `npm test`, `npm run build`. Дополнительно: полный Playwright (включая собственный вес → профиль → новая тренировка → экспорт → восстановление), сборка device и `cd android && ./gradlew assembleDebug testDebugUnitTest` с JDK 21 / Android SDK 36. Тесты на SQL.js используют отдельную БД и три аккаунта; браузерный API — изолированная локальная D1 либо явные заглушки. Рабочий сайт в тестах не используется.

В GitHub Actions добавлена отдельная проверка Android-сборки и Robolectric; публикации APK или сайта этот workflow не выполняет. Снимки новых экранов сохраняются в `artifacts/workflow` локально, без добавления сгенерированных изображений в git.
