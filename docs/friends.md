# Напарники и мобильные программы

Изменения подготовлены для следующего выпуска; сами по себе коммит и PR не обновляют работающий сайт или прежний APK.

## Поведение

- Нижняя панель на телефоне содержит все шесть разделов, включая «Программы» и «Друзья». Готовую программу можно выбрать, сохранить и начать тренировку, как на компьютере.
- У аккаунта есть постоянный случайный код из 12 hex-символов. Его можно скопировать или отправить ссылкой `/?friend=CODE`. После входа или регистрации ссылка открывает форму заявки; отправка требует нажатия кнопки.
- Заявку подтверждает только получатель. Повторный или встречный запрос не принимает её автоматически. Любая сторона может отменить заявку или удалить напарника.
- «Я в зале» — ручная отметка, а не определение геолокации. Название зала и фокус тренировки необязательны. Срок — 2 часа по серверному времени; можно закончить раньше или продлить. Отсутствие отметки не означает, что человек не тренируется.
- Лента содержит до 60 последних сохранённых тренировок за 30 календарных дней. Видны имя, название, дата, продолжительность, рабочие подходы и тоннаж однозначно записанных свободных весов. Заметки, упражнения, отдельные подходы, почта и масса тела не выдаются API.
- Респект относится к конкретной тренировке. Установка и снятие идемпотентны, повтор запроса не увеличивает счётчик. Себе и постороннему атлету респект отправить нельзя.
- В недельной шкале каждый участник вносит не более 3 тренировок. Избыток одного участника не закрывает ориентир остальных. Это мотивационный ориентир, а не назначение частоты тренировок. Даты журнала сохраняют прежнюю семантику; диапазон недели определяется часовым поясом наблюдателя.
- Список обновляется каждые 20 секунд только на открытом видимом экране, а также при возврате на вкладку, восстановлении сети и по кнопке. Ошибка сети сохраняет уже загруженный список и введённые поля. Мутации не показываются успешными до ответа сервера.

## Хранение и доступ

Серверный `FriendsRepository` использует `social_profiles`, `friendships`, `workout_kudos`. Связь — одна строка на упорядоченную пару аккаунтов. Журнал принадлежит `accounts.platform_id`, социальные связи — `accounts.id`. Авторизация остаётся в существующем `AccountService`; проверки Origin и JSON действуют и на новые маршруты.

API:

| Маршрут | Действие |
| --- | --- |
| `GET /api/friends` | Собственный код и статус, принятые напарники, заявки и сводки |
| `POST /api/friends/requests` | `{ code }`: код или ссылка приглашения |
| `PUT /api/friends/connections/:accountId` | Принять входящую заявку |
| `DELETE /api/friends/connections/:accountId` | Отклонить/отменить заявку, удалить связь |
| `PUT /api/friends/status` | `{ inGym, gym, focus }`: статус зала |
| `PUT /api/friends/kudos/:workoutId` | `{ given }`: установить/снять респект |

Сводки доступны только самому атлету и принятым напарникам. Незнакомцам нельзя искать пользователей по имени или почте. Код приглашения позволяет отправить заявку, но не читать тренировки. Отправка ограничена 30 попытками за 15 минут; исходящих связей и заявок — до 100. Удаление связи убирает взаимные респекты и прекращает последующие чтения/реакции. Уже загруженный чужой экран обновится при следующем запросе.

Социальные таблицы не входят в репликацию журнала и экспорт резервной копии. Android отправляет социальные запросы напрямую в подключённый `VITE_CLOUD_URL` с облачным Bearer-токеном; локальная SQLite не создаёт вымышленных напарников. Без облака экран предлагает подключить его в профиле. Истечение облачной сессии не завершает локальную сессию устройства.

## Проверка и выпуск

Обязательные проверки: `npx tsc --noEmit`, `npm test`, `npm run build`. API-тест работает с тремя отдельными аккаунтами в изолированном Miniflare D1: согласие, изоляция, CSRF, приватность сводок, срок статуса, идемпотентность реакций, удаление доступа и лимит запросов.

`tests/e2e/friends.spec.ts` полностью перехватывает API и проверяет размеры 320/360/390/768/1440 px, выбор готовой программы с запуском тренировки, принятие заявки, статус зала, реакции после перезагрузки, удаление напарника, приглашение через вход, сетевые ошибки и Motion. Скриншоты пишутся в `artifacts/friends/`; имена и тренировки в них — только тестовые fixtures. Регрессии прежних экранов — `tests/e2e/design.spec.ts`.

Перед облачным выпуском следовать существующему разделу README «Безопасное обновление»: проверить production Worker/D1, сохранить резервную копию, применить добавочную миграцию `0007_wise_rhodey.sql`, собрать и выполнить dry-run. Миграция не изменяет прежние аккаунты, тренировки или программы. Не импортировать тестовую базу. Сохранённый APK и его парные метаданные восстановить по прежнему процессу; обновление встроенного Android-интерфейса требует отдельной сборки и подписи APK.
