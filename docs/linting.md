# Линтер и baseline

ESLint включён без остановки работы: старые находки зафиксированы, новые падают.

## Команды

| Команда | Что делает |
|---|---|
| `npm run lint` | Сверяет находки с `.lint-baseline.json` и падает, если чего-то стало больше. Основная проверка для CI и перед коммитом. |
| `npm run lint:report` | Печатает все текущие находки с местом и текстом строки. Ничего не сравнивает, всегда с нулевым кодом. |
| `npm run lint:update-baseline` | Перезаписывает baseline текущим состоянием. Только осознанно: это способ узаконить долг, а не починить его. |

## Что проверяется

- `js.configs.recommended` — базовые правила JavaScript.
- `typescript-eslint` в режиме **без типовой информации**: типы проверяет `npm run typecheck`, а lint остаётся быстрым и не требует `project service`.
- `react-hooks/rules-of-hooks` (ошибка) и `react-hooks/exhaustive-deps` (предупреждение).
- `react-refresh/only-export-components` — предупреждение, чтобы правки не ломали горячую перезагрузку.

Пакет правил компилятора React (`react-hooks` recommended-latest) **не подключён**: это отдельная миграция со своим набором находок, и смешивать её с первым включением линтера нельзя.

## Как устроен baseline

`.lint-baseline.json` хранит счётчики по ключу `файл|правило|хеш текста строки`.

Хеш именно текста строки, а не номера: при выносе кода из файла номера сдвигаются, а содержимое остаётся — иначе baseline пришлось бы обновлять после каждого рефакторинга. Если находка исчезла, её ключ просто перестаёт встречаться: лишние ключи не считаются новыми находками, поэтому уменьшать долг можно вручную и постепенно.

Новая находка того же правила в той же строке, что и раньше, тоже считается новой — текст строки другой.

## Текущее состояние

- 113 находок в 101 ключе: 94 ошибки и 19 предупреждений.
- Почти всё — `@typescript-eslint/no-unused-vars` (неиспользуемые импорты и переменные), плюс `react-hooks/exhaustive-deps` и `react-refresh/only-export-components`.

Это зафиксированный долг, а не «всё чисто». Убирать его стоит рядом с обычными правками: вынос компонента или удаление мёртвого кода сам уменьшает счётчик, и `npm run lint` покажет это строкой «исправлено с прошлого раза».

## Проверка самого гейта

Гейт проверен в обе стороны: временная строка с неиспользуемой переменной роняла `npm run lint` с сообщением о новой находке, после её удаления проверка снова проходила.
